# Fictional-payload and room checklist

Complete this outside the repository for every consented session. Record only the final boolean
`fictionalPayloadVerified: true` and opaque payload/room references in repository-safe manifests.

- [ ] No real mail, parcel, badge, document, calendar, prescription, financial item, school/work
  item, licence plate, family photograph, wall display, or identifying view is visible.
- [ ] Devices use an offline test profile with fictional contacts and disabled notifications; no
  real lock screen, account, message, gallery, browser history, or wireless identifier is visible.
- [ ] Email examples use IANA-reserved `example.com`, `example.net`, or `example.org` domains.
- [ ] Telephone examples use a documented regulator-reserved fictional range for the displayed
  locale and are never dialled. The reservation source is retained outside the repository.
- [ ] Payment-card-like values are published test values used offline only, visibly marked TEST,
  never submitted to a payment service, and paired with fictional names/expiry/security values.
- [ ] Verification codes are generated for the scene, visibly marked DEMO, and unrelated to any
  service, account, device login, or active authentication session.
- [ ] QR/barcode payloads contain only a fixed harmless test token or an `example.com` URL; they do
  not encode contacts, Wi-Fi credentials, secrets, payment requests, or resolvable person data.
- [ ] Names, organizations, schools, and addresses are generator-created and checked not to match
  participants, crew, nearby locations, public figures, or real organizations.
- [ ] Props contain no copied real templates, logos implying authorization, signatures, government
  identifiers, or realistic credentials that could be misused.
- [ ] Harmless decoys are synthetic and contain no real information.
- [ ] A second reviewer inspected the live frame and all props before capture.
- [ ] If any check failed during a take, that take was rejected and securely deleted.
